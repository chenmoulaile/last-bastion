## 0. 快速摘要（若你只有 60 秒）

1. 用 **Godot 4.7.2 + GDScript** 做一款 640×360 像素横版射击游戏，人类方 vs 丧尸。
2. 玩法手感参照《破门而入：行动小队》：横版扫射、踹门破门、跳窗绳降、可破坏环境、近战推开、连击评分。
3. 敌人体系 1:1 对标《求生之路2》：普感尸潮 + Hunter/Smoker/Boomer/Charger/Spitter/Jockey/Tank/Witch 八种特感，全部数值见第 7 章，直接照表实现。
4. AI 队友双模式：**模式A** = L4D2 式四人小队（玩家+3 bot，会救人有战术）；**模式B** = 军方指挥（玩家指挥 4-8 名 AI 士兵，指令/阵型/兵种）。行为树规格见第 8 章。
5. 有一个 **AI Director** 中央导演系统管节奏：强度驱动尸潮、特感刷新、物资投放（第 9 章）。
6. 完整版内容：4 章 11 关、6 枪 3 近战 3 投掷、6 名可玩角色、评分解锁、20 成就、动态分层音乐。
7. 严格按第 14 章里程碑 M0→M9 顺序开发，每个里程碑有 DoD 验收门禁，通过后 git 提交推送。
8. 第 15 章是从零建仓到推送的完整命令序列，照抄执行即可。
9. 所有数值是初值，允许 ±30% 调优，但**相对平衡关系不可破坏**。
10. 规格未定义的细节，按第 1.2 节决策规则自行决策并记入 `DECISIONS.md`。

## 2. 项目总览与设计支柱

### 2.1 一句话定位

把《破门而入：行动小队》的横版扫射爽快感，装进《求生之路2》的尸潮压迫与特感博弈中，再用"双模式 AI 队友"给玩家一条真正的最后防线——你既可以带着 3 名精锐队友打突击，也可以像指挥官一样带着一整支军方小队平推街区。

### 2.2 设计支柱（所有设计决策必须服务于至少一条）

1. **爽快扫射 (Run & Gun)**：移动射击永远优先于站桩；门、木箱、油桶一切皆可破坏；每次击杀必须有"弹、亮、震"三件套反馈（hitstop、命中白闪、震屏）。
2. **尸潮压迫 (The Horde)**：普通僵尸永远成片出现，玩家永远处于"打不完但打得动"的状态；Director 保证节奏张弛有度，绝不让玩家长时间无事可做，也绝不让压力无休止地叠加。
3. **队友即防线 (Squad is the Wall)**：AI 队友必须真实有用——会救你、会卡位、会集火、会递药；指挥模式下玩家的每条指令必须在 0.2 秒内产生可感知的队形变化。
4. **一局一爽 (Score-Driven Replay)**：单关 8-15 分钟，结算评级 S-ABC，分数驱动解锁（武器/角色），鼓励反复刷关。

### 2.3 参考游戏机制拆解与本作映射

**《破门而入：行动小队》（Door Kickers: Action Squad, Kill House Games）**

| 参考机制 | 本作处理 |
|---|---|
| 横版侧视关卡、房间群结构 | 全部采纳 → 第 10 章关卡模板 |
| 踹门破门（对门后敌人造成硬直） | 采纳并扩展：门有耐久，僵尸也能挤破门 → 4.3 |
| 窗户跳入 / 绳降 | 采纳：窗户作为捷径入口 → 10.1 地形图块 |
| 可破坏掩体 / 油桶爆炸 | 采纳：油桶/煤气罐作为环境武器 → 4.3 |
| 近战推开 + 处决 | 采纳：近战推开是控尸保命核心 → 4.5 |
| 4 名可用角色各有专精 | 采纳：突击/医疗/重装/侦察 + 2 解锁 → 第 5 章 |
| 连击评分与结算评级 | 采纳强化 → 4.6、11.3 |
| 本地合作多人 | **不做**：以 AI 队友替代（见 2.5 范围边界） |

**《求生之路2》（Left 4 Dead 2, Valve）**

| 参考机制 | 本作处理 |
|---|---|
| AI Director 动态节奏 | 采纳并横版化 → 第 9 章 |
| 普感尸潮 + 事件尸潮 | 采纳 → 7.1 |
| 7 特感 + Tank + Witch 全套 | 1:1 对标横版化 → 7.2 |
| 倒地 / 队友拉起 / 治疗包 | 采纳 → 4.4 |
| 安全屋 / 检查点 / 终章撤离 | 采纳 → 10.5 |
| 听声辨位（特感标志性音效） | 采纳 → 12.2 |
| Versus 扮演特感 / 在线联机 | **明确排除**出 v1.0 范围 |

### 2.4 玩家幻想

你是疫情封锁区里的人类方武装小队长。街机化的爽快扫射是表，队伍管理与战场指挥是里。每一关都是从 A 点到 B 点的死亡突围，而你的底线是：**没有人被落下。**

### 2.5 v1.0 范围边界（防止范围蔓延）

- **包含**：4 章 11 关单机战役；小队/指挥双模式；8 特感 + 6 变异普感；6 枪 3 近战 3 投掷；6 名可玩角色；评分评级与解锁；20 项成就；三难度；动态音乐与全套音效；Windows/Linux/macOS 导出（Web 导出加分项）。
- **明确排除（禁止在本版实现）**：在线联机、本地双人、Versus 模式、关卡编辑器 UI（只做数据驱动的 .tres 格式）、移动端触屏适配、剧情过场动画（用文字简报卡代替）、剧情对话系统。

## 3. 技术选型与工程架构

### 3.1 引擎与版本

- **Godot 4.7.2 stable**（2026-08-18 发布的维护版本）。4.8 目前处于 beta 阶段，**禁止**用于本项目。下载：https://godotengine.org/download
- **语言：GDScript**（全项目统一，禁止混用 C#，理由：保证 Web 导出兼容性 + 保持 AI 可维护性）。
- 渲染器选择 **Compatibility（OpenGL）**：2D 游戏无增益于 Vulkan，且 Compatibility 是 Web 导出的唯一选择。
- 关键项目设置（`project.godot`）：

```ini

window/stretch/scale_mode="integer"

[rendering]
textures/canvas_textures/default_texture_filter=0   ; Nearest 像素完美
renderer/rendering_method="gl_compatibility"

[physics]
common/physics_interpolation=true
2d/default_gravity=1500.0
```

- 一个场景一个主脚本，脚本文件名 = 场景文件名；

### 3.3 Autoload 单例（固定 6 个，不得增删顺序影响——按下列顺序注册）

| 单例 | 职责 | 关键接口 / 信号 |
|---|---|---|
| `EventBus` | 全局信号总线，系统间唯一通信方式 | 信号：`enemy_died(kind, pos)`、`player_downed`、`player_rescued`、`ally_pinned(ally)`、`horde_started(count)`、`special_spawned(kind)`、`door_broken(pos)`、`unlock_earned(id)`、`level_completed(score, rank)` 等 |
| `GameManager` | 全局流程状态机、当前模式/章节/关卡/难度、解锁数据 | `change_state()`、`start_level(id, mode, difficulty)`、状态枚举 `BOOT/MENU/BRIEFING/PLAYING/PAUSED/RESULT` |
| `DirectorSystem` | 第 9 章：强度统计与刷怪指令 | `intensity: float`、`tick()` 每秒、指令信号 `request_horde(count)`、`request_special(kind)` |
| `AudioManager` | 分层 BGM + SFX 池 | `play_music_layer(layer, on)`、`play_sfx(id)`、`play_sfx_2d(id, pos, max_dist)` |
| `SaveSystem` | 单槽位存档，原子写入 | `save()`、`load()`、`mark_achievement(id)`、`add_score_total(n)` |
| `ConfigManager` | 键位重映射/音量/显示设置 | `get_action_key(action)`、`set_volume(bus, v)` |

**通信规则**：禁止跨场景 `get_node("../..")` 直接引用；一切跨系统通信走 `EventBus` 信号。父场景对子节点的直接引用允许一层。

### 3.4 数据驱动设计（Resource 表）

每个僵尸/武器/角色 = 一个自定义 Resource 类 + 若干 .tres 实例。示例（僵尸）：

```gdscript
class_name ZombieData
extends Resource

@export var id: StringName
@export var display_name: String        # 中文显示名
@export var max_hp: int
@export var walk_speed_min: float
@export var walk_speed_max: float
@export var attack_damage: int
@export var attack_interval: float
@export var score_value: int
@export var behavior_id: StringName     # 挂接行为脚本标识
@export var tint: Color                 # 素材复用调色
@export var size_scale: float = 1.0     # 复用模板时的缩放
@export var anim_map: Dictionary        # 动画名 -> SpriteFrames 动画键
```

武器表 `WeaponData`、角色表 `CharacterData` 同理（字段见第 5、6 章表格列名）。**第 5、6、7 章的所有数据表必须 1:1 落成 .tres 文件，这是验收项。**

### 3.5 碰撞层矩阵（编号强制，不得改动）

| 层 | 名称 | 成员 | 与哪些层碰撞 |
|---|---|---|---|
| 1 | WORLD | 地形/墙/静态物 | 全部 |
| 2 | PLAYER | 玩家角色 | 1, 4, 5, 7 |
| 3 | ALLY | 队友与士兵 | 1, 4, 5 |
| 4 | COMMON | 普通感染者 | 1, 2, 3, 4, 6 |
| 5 | SPECIAL | 特殊感染者 | 1, 2, 3, 4, 6 |
| 6 | PROJECTILE | 子弹/投掷物 | 1, 4, 5, 7 |
| 7 | INTERACTABLE | 门/物品/撤离区/机关 | 2, 6 |

补充：普感与普感同层（4）但**不做逐体物理互撞**，用流场分离力简化（见 7.1 实现要点），防止百只单位互相卡死。

### 3.6 GDScript 编码规范

- 命名：文件/函数/变量 `snake_case`，类名 `PascalCase`，常量 `SNAKE_CASE`；信号名用过去式或名词短语（`player_died`、`ammo_changed`）。
- 所有函数参数与返回值加类型标注；每个文件一个 class，声明 `class_name`。
- `_process()` 只做表现（动画/粒子/UI 抖动），游戏逻辑一律放 `_physics_process()`。
- 禁止魔法数字直接内联：需要平衡的数值进 Resource，纯表现数值可用常量并注释。
- 每个超过 20 行的函数，头部写 2-3 行中文注释说明意图。
- 状态机模式统一：`scripts/states/state_machine.gd` 通用实现 + 每状态一个文件。

### 3.7 性能预算（硬性指标，进 CI 冒烟测试）

| 指标 | 预算 |
|---|---|
| 同屏普感 | ≤ 120（Director 负责超限停止生成） |
| 同屏特感 | ≤ 4（Tank 独占屏，Witch 不计） |
| 子弹池 / 粒子池 | 子弹 200、血雾实例 64、弹壳 32，全部对象池化 |
| 帧率 | 60 FPS（GTX 1050 级硬件，全特效） |
| 每物理帧 raycast | ≤ 64 次（AI 视线分帧：每帧只更新 1/4 成员的感知） |
| 内存峰值 | < 600 MB |

通用对象池：`scripts/utils/object_pool.gd`（`acquire()` / `release(node)`），供子弹、僵尸、尸体、粒子四类复用。

### 3.8 相机与渲染表现

- `Camera2D` 跟随玩家：`position_smoothing_speed = 8.0`，向移动方向前瞻 40px；`limit_*` 设为关卡边界。
- 房间内所有 actor 的父节点开启 `y_sort_enabled` 保证前后遮挡正确。

## 4. 核心玩法设计

### 4.1 战役主循环

主菜单 → 选择关卡（按章节解锁）→ 确认模式（小队/指挥，关卡有预设可覆盖）→ 确认难度 → 出击简报卡（关卡名 + 目标 + 新增威胁提示）→ 进入关卡：从安全屋出发 → 横向推进 → 事件（尸潮/特感/防守）→ 中途检查点 → 到达撤离点（部分关卡为"防守波次 + 载具撤离"终章式）→ 结算（分数滚动/评级/解锁）→ 下一关或重刷。

失败条件：**玩家角色死亡**（小队模式可从检查点重试；指挥模式玩家死亡 = 全队溃败，直接回检查点）。AI 队友死亡不导致失败，但影响战力与结算分。

### 4.2 玩家操控（默认键位，全部可在设置中重映射；手柄按标准映射）

| 动作 | 键盘默认 | 手柄 |
|---|---|---|
| 左右移动 | A / D | 左摇杆 |
| 跳跃 | Space | A 键 |
| 蹲/潜行 | S 按住 | B 键 |
| 上/下楼梯与平台 | W / S | 左摇杆上下 |
| 瞄准方位（平射/斜上/正上/斜下/正下） | 移动方向 + 开火键组合 | 右摇杆 |
| 开火 | 鼠标左键 / J | RT |
| 近战推开 | F / K | X 键 |
| 换弹 | R | Y 键 |
| 切换武器（主/副/近战） | Q / 滚轮 | LB |
| 投掷物 | G | RB |
| 互动（踹门/救人/拾取/递药） | E | X 键（交互物附近出现提示） |
| 角色技能 | Shift | LT |
| 指令轮盘（仅指挥模式） | 数字 1-4 / Tab 展开 | 十字键 |
| 暂停 | Esc | Start |

移动手感参数（必须精确实现）：跑速 220 px/s；蹲行 110；跳跃初速 -560；重力 1500；土狼时间 0.08s；跳跃缓冲 0.10s；**滑铲**：跑动中按蹲 → 低身滑行 0.35s（前 0.15s 无敌帧，CD 1.2s）——用于滑过 Hunter 扑击线与从 Witch 身边脱身，是高手向核心操作。

普感抓咬不会拖慢玩家移动，但会打断换弹与使用医疗包（压迫感来源）。受击后有 0.5s 无敌帧防瞬秒。

### 4.3 门与环境互动（行动小队灵魂机制）

- **门类型**：普通木门（耐久 100，可踹破也可被挤破）、铁门（需钥匙/电焊，剧情门）、双开玻璃门（任意子弹一发即碎）。
- **踹门**：面向门按 E → 0.2s 踹击动画，门飞开，门后 60px 内的普感/特感（Tank、Witch 免疫）受 10 伤害 + 0.8s 硬直。破门换来的是主动权——这是行动小队最爽的一瞬间，动画与音效必须砸重做足。
- **僵尸挤门**：门外 ≥3 只普感持续抓挠时对门造成 20 DPS；门破后尸群涌入。玩家在门内防守时能听到耐久告急的木裂声（音效三档：完好/开裂/将破）。
- **窗户**：可跳跃翻入；高处窗户按住 E 绳降缓落；部分窗户被木板钉死（近战 1.2s 拆除）。
- **可破坏物**：木箱（近战/子弹破坏，概率掉落补给）、油桶与煤气罐（受击爆炸：120px 范围 80 伤害 + 地面燃烧 3s）、废弃汽车警报（子弹击中车身概率 20% 触发小尸潮事件——风险道具）。
- **机关**：L4 写字楼电梯开关、L9 装甲车随行掩体（见第 10 章关卡表）。

### 4.4 生命与救助系统（L4D2 式，全照搬规则）

- HP 上限 100；另有**临时 HP**（药丸 +50，每秒衰减 1 点，优先扣除）；界面用红色实条 + 白色叠加段显示。
- **倒地 (Incapacitated)**：HP 归零触发。倒地后可缓慢爬行、只能用手枪，20s 流血倒计时归零即死亡；每关内第 3 次倒地直接死亡（L4D2 规则）。
- **救助**：队友/士兵走近按住 E 3 秒拉起（恢复 30 点临时 HP）。玩家被特感控制（扑/缠/冲/骑）时，必须由队友近战打断或击杀特感解除——因此**模式A里队友的救助 AI 是生死线**。
- **黑白模式**：累计倒地 ≥2 次被救起后，画面变灰、HP 上限降为 1，直到使用医疗包解除。UI 加灰色滤镜 + 边框闪烁。
- **医疗包**：恢复 80% 缺失 HP（向上取整），使用需 4s 引导（被打断则浪费一半进度）；**药丸**：+50 临时 HP，即用即得。
- 玩家死亡：小队模式 = 从检查点重来；指挥模式 = 溃败重来。AI 队友死亡：本关退出战斗，抵达下一个安全屋/下一关时复活（指挥模式士兵死亡**不**复活，只能靠检查站的援军房补兵）。

### 4.5 战斗系统（Hitscan 即时弹）

- 枪械全部为 **hitscan**：发射瞬间 `PhysicsRayQuery` 从枪口到准星方向 × 射程，命中第一个有效碰撞体。表现层：2 帧枪口火光 + tracer 线段（存活 0.06s）+ 弹壳粒子 + 命中火花/血雾。
- **散布模型**：基础散布(°) + 移动/跳跃惩罚 + 连射累积（每发 +0.3°，停火 0.4s 回落）。狙击枪例外：开镜（按住右键/左摇杆按下）散布 0.3°，腰射 5°。
- **伤害公式**：`最终伤害 = 基础伤害 × 距离衰减 × 爆头倍率`。有效射程外每 100px 衰减 15%（下限 40%）；命中判定盒上 1/4 区域视为爆头 ×2（普感/ Hunter / Jockey 有头部盒，Tank/Witch 无）。
- **近战推开**：46px 扇形 120°，伤害 15，对普感 100% 硬直 0.8s + 击退 120px，CD 0.45s。手感要求：hitstop 0.04s + 大幅度击退 + 清脆音效——这是被尸群贴脸时的保命技，必须干脆利落。
- **投掷物**：手雷（3s 引信，140px 范围 150 伤害）、燃烧瓶（落点 90px 火区 8 秒，12 DPS，对普感大杀器+区域封锁，对 CEDA 防护服无效）、胆汁瓶（命中点吸引普感 15 秒——反向利用 Boomer 机制做战术道具）。

### 4.6 连击与评分

- 击杀得分见第 7 章各僵尸表。**连击窗口 4 秒**：窗口内任意击杀刷新计时并 +1 连击；分数倍率 = min(1 + 连击数 × 0.25, 5.0)。
- 连击断：窗口超时、玩家倒地（连击清零）。受击不清连击（保持爽快）。
- **结算公式**：`总分 = 击杀分累计 + 关卡基础分 100000 − 超时罚(每超 10s 扣 2000) + 救助奖励(每次 5000) + 无伤奖励(20000)`。
- **评级**：关卡 .tres 内配置"理论满分基准值"，S ≥ 95%、A ≥ 80%、B ≥ 60%、C 为其余。

## 7. 僵尸图鉴（1:1 对标求生之路2）

总设计原则：**普感造"海"，特感造"局"。** 每只特感都是一道必须用特定解法拆掉的谜题；Tank 与 Witch 是关卡级事件。所有数值 1:1 落成 `resources/data/zombies/*.tres`。

### 7.1 普通感染者 (Common Infected)

| 属性 | 数值 |
|---|---|
| HP | 30（爆头 ×2：15 以上单发伤害即爆头清除） |
| 移速 | 120–180 px/s 随机个体差异；15% 个体为奔跑型（220） |
| 攻击 | 5 伤害 / 0.5s 抓挠间隔 |
| 感知 | 视野 260px / 140° 扇形；枪声全图传播（900px 内必警觉） |

| 死亡 | 4 方向溅倒布娃娃 + 血雾粒子；尸体 10s 后淡出（对象池回收） |

行为细节（氛围核心，必须做出 L4D2 的"活着的世界"感）：
- **游荡**：空闲时随机做小动作——原地呻吟、踱步、扒墙、呕吐、蹲坐；每 3-8 秒换一个。
- **惊动链**：一只发现玩家 → 尖叫 → 80px 范围尸群连锁惊动（尖叫可继续传染，形成涟漪）。

- **事件尸潮**：警报器/汽车警报/Boomer 胆汁/小丑死亡触发，强度 ×1.5（数量 +50%）。
- **实现要点（性能）**：普感之间不做逐体物理互撞，用**分离力**简化——同层重叠时按相互排斥向量推开（boids separation），避免 120 只单位物理卡死。寻路用简化的**平台图 A\***：waypoint 撒点规范见附录 A（平台两端、楼梯口、门窗必标，间距 ≤240px）。

### 7.2 特感 (Special Infected) —— 8 种

**通用规则（先读，特感表都引用它）**：
- **刷新**：Director 控制（默认 25s ± 8s，强度越高越短），每次 1-2 只组合生成；位置规则 = 玩家视野外 400-700px、平台图可达的刷点；同屏特感 ≤4。
- **控制解除**：所有"被控"状态可由队友近战打断或击杀特感解除；被控者可小幅挣扎（移动速度 −60% 的方向拉扯）。
- **打断规则**：单次伤害 ≥30（霰弹近距/狙击）可打断 Hunter 扑击与 Charger 冲锋（造成 0.4s 硬直）——为霰弹枪和队友枪线提供反制窗口。
- **控制免疫**：被控解除后 3s 控制免疫，防连锁秒控。
- **分值**：见各表"分值"字段，乘以连击倍率。

| 分值 | 600 |

定位：**尸潮触发器**。威胁不是本体而是它引来的尸潮。应对：远距击杀但要预判爆炸距离；近身一律先推开再杀。

### 7.4 ZombieBase 统一接口（脚本契约，强制）

```gdscript
class_name ZombieBase
extends CharacterBody2D

signal died(zombie_id: StringName, hit_pos: Vector2)

func apply_damage(amount: int, from_dir: Vector2, is_head: bool) -> void: ...
func apply_stagger(duration: float) -> void: ...
func apply_knockback(force: Vector2) -> void: ...
func enter_control(target: Node2D) -> void: ...   # Hunter/Smoker/Charger/Jockey 控制入口
func release_control() -> void: ...
func get_data() -> ZombieData: ...
```

实现要求：所有特感基于 `scripts/states/state_machine.gd` 状态机框架，**每个状态一个文件**（如 `hunter_state_pounce.gd`），便于增量实现与单元测试。受击硬直、死亡、控制是三个公共状态，在 ZombieBase 实现，子类只写特有状态。

## 8. AI 队友系统（双模式）—— 本作差异化核心

### 8.1 统一架构

两种模式共用一套底座：`AllyBase`（CharacterBody2D）+ **自研轻量行为树** + 黑板 + 感知器。

**自研行为树**（`scripts/behavior_tree/`，约 300 行，禁止第三方插件依赖）：

- 节点类型：`Selector`（顺序选择，成功即返回）/ `Sequence`（顺序执行，失败即返回）/ `Parallel`（并行，任一成功即成功）/ `Condition`（谓词）/ `Action`（动作）/ `Cooldown(t)` / `Invert`。
- **黑板 (Blackboard)**：每 Agent 一个 Dictionary，键：`target_threat`、`pinned_ally`、`downed_ally`、`leader_pos`、`order`、`last_shot_time`、`formation_slot`。
- 结构声明方式：在 Agent 的 `_build_tree()` 中用代码组装（可读、可 diff、可热调）：

```gdscript
func _build_tree() -> BTNode:
    return BT.selector([
        BT.cond(func(bb): return bb.pinned_ally != null),          # 有人被控
        BT.action(_rescue_pinned),
        BT.cond(func(bb): return bb.downed_ally != null),          # 有人倒地
        BT.action(_rescue_downed),
        BT.cond(func(bb): return bb.target_threat != null),        # 有威胁
        BT.action(_engage),
        BT.action(_follow_formation),
    ])
```

**感知器 Perception**：
- 视觉：前方 300px / 120° 扇形，raycast 遮挡检查；**分帧**：每物理帧只更新 1/4 成员的感知（性能预算 3.7）。
- 听觉：订阅 `EventBus` 的 `gunshot`、`zombie_scream`、`horde_started` 信号。
- 威胁评估：`threat_score = 威胁等级 × 距离衰减`；等级：Tank=100、正在控制队友的特感=90、其他特感=50、普感=5。

**射击 AI（命中率模型，不做弹道模拟）**：
- 每 0.4s 判定一次：`命中率 = 0.65 × 距离系数 × 目标速度系数`；命中即按其武器数据 ×0.85 弱化系数造成伤害。
- 换弹走真实流程（硬直 + 音效）；弹药耗尽 → 后撤换弹或切副武器。
- 枪口必须真实发光发声（视觉欺骗：AI 的 tracer 与音效让玩家感到"队友在真实作战"）。

### 8.2 模式 A：四人小队（L4D2 式）

- **编制**：玩家 + 3 名 AI 队友；从已解锁角色池自动取 3 名（玩家可在出击简报页手动指定）；每名队友固定专属主武器 + 无限备弹副武器。
- **行为树优先级（从高到低，严格顺序，不得调换）**：

| 优先级 | 行为 | 细则 |
|---|---|---|
| 1 | 自救 | 被特感控制 → 挣脱计时（3s）；HP<25 且附近无敌人 → 自用医疗包 |
| 2 | 救援 | 任一队友/玩家**倒地或被控** → 走近执行救助（3s）或近战打断控制；多人倒地按距离近的先救 |
| 3 | 交战 | 有威胁 → 站位开火。目标优先级：Tank > 正在控制队友的特感 > 其他特感 > 普感；与目标保持 200-350px（霰弹队友反常规贴至 150px） |
| 4 | 补给 | 自身备弹 <30% 且 100px 内有弹药堆 → 前往补充；玩家 HP<50 且自己背包有医疗包 → 主动递药（L4D2 bot 经典行为） |
| 5 | 编队跟随 | 无战事 → 环形编队跟随玩家，槽位 = 玩家后上方 / 后下方 / 侧翼，保持 150-300px |
| 6 | 归队 | 距玩家 >400px 且掉队 5s → 以 1.3× 移速归队 |

- **卡位设计**：防守事件中，队友自动占据 `LevelEvent` 定义的 anchor 点（门口/高台/玩家 ±1 层平台），形成火力交叉——anchor 点由关卡数据配置。
- **复活规则**：队友死亡 → 本关退出 → 抵达下一个安全屋或下一关时满状态复活。
- **友军伤害**：默认关闭；专家难度开启（0.5 倍系数）。
- **语音钩子**：受击/救援/发现特感三类，各 3 变体随机播——成本极低，氛围收益极高。

### 8.3 模式 B：军方指挥（大部队模式）

- **编制**：玩家（小队长）+ 4-8 名士兵（每关 .tres 配置编制；上限 8，性能考虑）。

| 兵种 | 武器 | HP | 特性 |
|---|---|---|---|
| 步枪手 Rifleman | AR-15（×0.8 伤害） | 80 | 均衡；编制默认占 60% |
| 机枪手 Gunner | LMG | 110 | 移速 150；开火需 0.8s 架枪；HOLD 时优先占高台 |
| 医疗兵 CombatMedic | SMG | 80 | 自动治疗 80px 内 HP<50 的伤兵（15s CD，每次 +25） |
| 爆破手 Demolisher | 霰弹 | 90 | 携 2 枚手雷；尸潮密集点自动投掷（60s CD） |

- **指令集**（快捷键 1-4 / 手柄十字键；0.2s 内全队响应，配播指令音效与头顶图标）：

| 指令 | 行为 |
|---|---|
| 1 跟随 FOLLOW | 默认状态。纵队跟随玩家（身后 3 列 × 间距 80px） |
| 2 推进 ADVANCE | 朝准星方向推进至 400px 处，交火驻守 |
| 3 防守 HOLD | 就地展开：机枪手架枪/占 anchor、步枪手找掩体或门口卡位、医疗兵居中、爆破手机动 |
| 4 集火 FOCUS | 标记准星方向最近威胁（含特感），全员优先攻击该目标直至其死亡 |

- **阵型规则**：FOLLOW=纵队；HOLD=以玩家为中心 180px 半圆分布（机枪手必占高台/门口 anchor）；ADVANCE=横排 2 列推进。
- **士兵损耗与补兵**：士兵死亡**本关永久损失**；检查站设"援军房"（补满编制，数量从关卡预算扣除）——指挥模式的核心张力是"兵是消耗品"。
- **士兵数值弱于模式A队友**：命中率 ×0.75、无技能，但胜在数量与火力网。
- **溃败规则**：玩家死亡 = 全队溃败（与模式A的关键区别，紧张感来源）。
- **指挥 UI**：左上小队状态板（每兵一行：兵种色块 + HP 条 + 状态徽章）；指令生效时全员头顶图标闪烁 0.5s + 横幅"全队——推进！"。

### 8.4 模式选择与战役安排

- 每关 .tres 定义 `default_mode: SQUAD | COMMAND`；关卡选择页允许玩家覆盖（指挥模式成绩带徽章标记，成就分开统计）。
- 叙事安排：第 1-2 章 = 小队模式（特勤小队突围）；第 3 章 = 指挥模式（收拢军方残部）；第 4 章 = 玩家自选。

### 8.5 AI 调试工具（开发期强制实现，F10 面板）

- 实时显示每个 AI 的黑板关键字段、当前行为树活动路径、感知目标列表；
- "生成特感"按钮：任意种类、点击地图任意位置生成；
- 时间缩放切换 0.25× / 1× / 2×（调行为树必备）；
- 视线/寻路可视化（画 waypoint 图与 raycast 射线）；
- 全部调试代码用 `if OS.is_debug_build()` 包裹，发布版剔除。

## 9. AI Director（动态难度导演）

对标 L4D2 AI Director 并横版化。`DirectorSystem` 是 Autoload 单例：**只读统计 + 只发指令**，绝不直接操作节点（指令通过信号发给关卡控制器 LevelRunner 执行）。

### 9.1 强度模型

- `intensity ∈ [0, 1]`，每秒更新：

```
intensity += 0.02                     # 基础爬升
intensity += 0.10 × 本秒玩家受击次数    # 交火升温
intensity −= 0.15                     # 尸潮结束后 8s 休整窗口内每秒
intensity −= 0.05                     # 玩家位于安全屋内每秒
```

### 9.2 输出决策（每秒 tick）

| intensity | 特感刷新计时 | 尸潮事件 | 备注 |
|---|---|---|---|
| < 0.30 | 32s ± 10 | 不触发 | 休整期：氛围游荡尸为主 |
| 0.30–0.60 | 25s ± 8 | 8% 概率/tick | 常规压力 |
| 0.60–0.85 | 18s ± 6 | 15% 概率/tick | 尸潮 + 1 特感组合 |
| > 0.85 | 12s ± 4 | 必触发 | 压迫峰值 → 触发后强制 8s 休整 |

### 9.3 物资节奏（雪中送炭算法）

- 统计全队 HP 均值 < 45% 时 → 前方 2000px 内刷新 1 个医疗包（一次性标记，防重复刷）；
- 全队主武器备弹均值 < 20% 时 → 前方刷新 1 个弹药堆；
- 这是 L4D2"永远刚好够用"的手感来源，必须实现。

### 9.4 指令与执行分离

```
DirectorSystem.tick() ──信号──> LevelRunner（关卡控制器）
   request_horde(count)            spawn_horde(count, edge|doors)
   request_special(kind)           spawn_special(kind)  ← 按权重表抽选 + 刷点规则
   request_supply(type, pos)       spawn_pickup(type, pos)
```

所有生成一律走 ZombiePool / FxPool 对象池。Director 在玩家进入安全屋时挂起，结算时重置。

## 10. 关卡设计与编辑规范

### 10.1 Tilemap 规范

- 图块尺寸 **16×16**；图层从下到上：
  1. `BG_Parallax`（视差远景，独立 ParallaxBackground 层）
  2. `BG_Decor`（背景装饰，无碰撞）
  3. `Terrain`（实心地形，生成物理层 1）
  4. `Platforms`（单向平台：可跳上、按 S+跳 下穿）
  5. `Hazards`（水/火/酸危险格，接触伤害）
  6. `Interactables`（门位/机关/拾取位标记，实体单独挂场景）
  7. `Foreground`（半透明前景遮挡：窗框/栏杆，玩家重叠时 alpha → 0.4）
- **地形图块集（必做清单）**：外景地面/砖墙/草地、室内墙/地板/天花板、楼梯（45° 踏步 + 自动台阶判定：踩上即按地面高度吸附）、单向平台、窗（可翻入）、门位（门实体）、危险格、可破坏物标记位。
- 地形使用 Godot terrain set（peering bits）自动连接，降低手工铺设成本。
- **横版寻路 waypoint 规范（附录 A）**：每个平台两端必标；楼梯口/门/窗必标；间距 ≤240px；用 `Path2D` 可视化，调试面板可开关显示。

### 10.2 关卡结构模板（prefab 场景，复用拼接）

| Prefab | 尺寸参考 | 用途 |
|---|---|---|
| SAFE_ROOM | 320px 宽 | 安全屋（起点/检查点/终点） |
| STREET | 800-1200px | 街段：掩体+废弃车+游荡尸 |
| APARTMENT | 480px，双层 | 楼内战斗：楼梯+房间群+破门 |
| PLAZA | 1000px 开阔 | 尸潮战场：油桶/煤气罐阵 |
| CORRIDOR | 400px 窄道 | 近战瓶颈：尸群挤压战 |
| ROOFTOP | 600px | 天台段：横向风+狙击位 |

### 10.4 事件系统 (LevelEvent)

- 触发器 `TriggerRegion`（Area2D）：`enter`（进入区域）/ `interact`（交互触发）/ `alarm`（警报联动）/ `timer`（倒计时）四类。
- 事件数据结构（.tres 配置，不写死代码）：

```
events: [
  {
    trigger: {type: "enter", region: Rect2(...)},
    actions: ["spawn_horde:25", "lock_doors", "dialog:briefing_02"],
    once: true
  }
]
```

- 可用 action：`spawn_horde(n)` / `spawn_special(kind)` / `lock_doors` / `unlock_doors` / `spawn_supply(type, n)` / `dialog:card_id`（文字简报卡）/ `defense_wave(waves)`（防守事件）/ `spawn_boss(kind)`。
- **防守事件** = `lock_doors` + `defense_wave` + 解除条件（全灭 / 计时 / 到达点）。
- 文字简报卡：事件前后各一张（替代过场动画，UI 层呈现，3 行以内文案）。

### 10.5 安全屋 / 检查点 / 撤离终章

- **起点安全屋**：补给全满 + 武器柜（切换初始武器）+ 难度告示牌 + 教学tips（新机制关）。
- **中途检查点**：死亡重生点；补给半数；指挥模式的援军房所在。
- **撤离终章**（L6/L11 与部分关尾段）：到达触发防守波次 → 载具/直升机倒计时 15s → 任意存活成员进入撤离区即结算（结算页统计全队生死，影响"无人落下"成就）。

## 12. 音频规格

### 12.1 动态分层 BGM（Director 驱动，L4D2 体验的核心移植）

- 每关音乐由 **4 层 stems** 组成（同曲不同强度，Loop 对齐）：
  1. `CALM`：氛围底（低音铺底 + 稀疏鼓点）
  2. `COMBAT`：节奏层（紧张弦乐/电子脉冲）
  3. `HORDE`：全奏层（尸潮爆发）
  4. `TANK`：Tank 专属（低音吼 + 工业打击乐，独占混音）
- 切换规则：intensity 映射层音量——0–0.3 仅 CALM；0.3–0.6 叠加 COMBAT；>0.6 叠加 HORDE；Tank 存活期间 TANK 独占。层间交叉淡入 1.5s（`AudioTween`）。
- 特殊曲目：安全屋内播放"幸存者电台"轻快变奏；结算页 S 评级专属小旋律；主菜单主题压抑合成器。

### 12.2 SFX 清单（全部接入 AudioManager 池，2D 定位 + 距离衰减）

**特感标志性音效（听声辨位核心，缺一不可）**：

| ID | 触发 | 描述 | 变体数 |
|---|---|---|---|
| hunter_scream | 蓄力扑击前摇 | 金属质高频尖啸，由远及近 | 3 |
| smoker_cough | 锁定/伸舌前 | 湿咳带喉音 | 3 |
| boomer_burp | 接近/呕吐 | 低沉打嗝 + 黏液音 | 2 |
| charger_roar | 冲锋前摇 | 火车头式低吼加速 | 2 |
| spitter_hiss | 吐酸前 | 沸水嘶嘶 | 2 |
| jockey_giggle | 接近中 | 畸变咯咯笑（最阴森） | 3 |
| tank_bell | Tank 出场 | 钟声 + 吼叫（触发 BGM 切换） | 1 |
| witch_cry | 常态环境音 | 哭泣声，**音量随玩家距离增大**（距离预警） | 2 |

**枪械/近战**：m9 / rifle / smg / shotgun / sniper / lmg / axe / katana / chainsaw，每支 3 变体防重复感；附加换弹、空仓、拾取音。

**通用**：门踹（重低音 + 门轴爆裂）、木裂三档（门耐久预警）、警报、油桶爆炸、燃烧持续、拾取、救助完成、倒地心跳（黑白模式循环）、结算章戳、成就解锁、UI 点击/确认/返回。

**语音钩子**：队友受击 / 救援 / 发现特感 三类各 3 变体（简短喊话，可用程序变调生成）。

来源策略：freesound.org（CC0 过滤）+ Kenney 音频包（CC0）+ sfxr/jsfx 生成补充；全部转 OGG，峰值归一 −6dB。允许 AI agent 用程序化合成兜底，但特感标志音必须可辨识。

### 15.4 提交规范（Conventional Commits）

- 类型：`feat` / `fix` / `art` / `audio` / `docs` / `perf` / `refactor` / `chore` / `test`
- 作用域：`player` / `zombies` / `ai` / `levels` / `ui` / `audio` / `director` / `save` 等
- 示例：
  - `feat(zombies): implement hunter pounce state machine with interrupt window`
  - `fix(ai): allies stuck on platform edges when following formation`
  - `perf(common): cap horde particles via object pool`
- 每个任务至少一提交；禁止 `update files` 类无效信息；每个里程碑必须打 tag（`v0.1.0-m0` … `v1.0.0`）。

### 15.5 CI（可选但推荐）：GitHub Actions Web 导出

`.github/workflows/export-web.yml`（tag 推送时导出 WASM 并发布到 GitHub Pages）：

```yaml
name: export-web
on:
  push:
    tags: ["v*"]
jobs:
  export:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: godotengine/godot-colab-ci@v1     # 或 abarichello/godot-ci
        with:
          godot-version: "4.7.2"
      - run: godot --headless --export-release "Web" build/index.html
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: build/
```

（若 CI 模板与最新 Action 版本不符，允许查阅 Action 文档后替换为等价配置，记入 `DECISIONS.md`。）

### A. 横版寻路 waypoint 规范

- 每个平台两端必标；楼梯上下口、门内外、窗内外必标；同层间距 ≤240px；
- 高危区（Witch 驻留、Tank 事件区）旁的 waypoint 标记 `danger_weight +2`，AI 寻路绕行；
